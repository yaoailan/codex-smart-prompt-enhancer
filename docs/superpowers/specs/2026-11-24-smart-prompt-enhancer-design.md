# Codex 智能提示词增强器设计

日期：2026-11-24

## 1. 目标

为 Codex 增加默认启用的“智能提示词增强”能力，让用户不必每次手动写“增强一下”，也不必通过 `@技能` 调用。

增强后的提示词应更清楚地表达用户的真实目标、约束、执行范围、禁止事项、成功标准和待确认信息，同时避免把简单请求或控制语句处理得冗长。

## 2. 非目标

- 不修改 Codex 桌面程序本体或其安装文件。
- 不绕过 Codex 的权限、审批或安全机制。
- 不自动替用户做不可逆或高风险决定。
- 不隐藏原始请求，也不擅自改变用户明确表达的目标。
- 不在仓库、日志或公开材料中包含密钥、Cookie、邮箱、代理配置或其他私人数据。

## 3. 用户流程

### 3.1 默认智能增强

全局规则要求 Codex 在每条用户消息到来时先做轻量路由：

- **增强后预览**：复杂、含糊、跨步骤、需要工具副作用、存在失败或误操作风险、缺少关键上下文但可以合理补全的任务。
- **直接处理**：简单事实问答、信息完整且明确的小任务、确认/继续/执行/取消、增强开关命令、纯翻译或格式转换等不需要扩写的请求。

增强模式先只输出预览，不调用工具，也不产生外部副作用。预览包含：

1. 增强后的提示词；
2. 相对原请求补充了哪些关键假设；
3. 用户可以直接回复“执行”，或先修改预览。

只有用户确认，或用户编辑预览后明确要求执行，才进入实际执行。

### 3.2 开关

用户可以用自然语言说：

- “开启提示词增强”
- “关闭提示词增强”
- “提示词增强状态”

安装后的技能提供状态脚本，确保开关行为一致、可测试。默认状态为开启。

### 3.3 用户可见性

预览必须明确标注为“提示词增强预览”，避免用户误以为任务已经开始执行。

## 4. 增强内容结构

预览使用按需裁剪的结构，不要求每次填满所有栏目：

- **目标**：要达成的可验证结果。
- **背景与上下文**：已知信息、必要时合理推导的假设。
- **执行范围**：允许修改或访问的范围。
- **必须满足**：技术和业务约束。
- **不要做**：明确的禁止事项和安全边界。
- **成功标准**：如何判断完成。
- **待确认项**：无法安全推断、必须由用户决定的事项。

简单任务只输出一至两项，不得为了形式完整而扩写。

## 5. 路由与安全原则

### 5.1 必须预览的任务

- 多步骤实现、调试、发布或迁移。
- 会修改文件、系统设置、Git 历史、远程仓库或外部服务。
- 有网络发布、费用、隐私、安全或不可逆风险。
- 原始需求存在关键歧义，不同理解会导致明显不同结果。
- 用户要求“全部做完”“自动处理”但未给出可安全推断的具体范围。

### 5.2 直接处理的任务

- 一般知识问答和解释。
- 用户已确认的预览或后续控制语句。
- 信息完整的单步命令。
- 用户要求只做简单文字处理。
- 增强功能的开关与状态查询。

### 5.3 安全边界

- 预览不是授权。
- 增强不能扩大用户原始请求的权限或范围。
- 若缺失信息会显著影响结果且不能安全推断，在预览的“待确认项”中明确提出。
- 涉及破坏性操作时，预览必须写明准确目标和恢复方式。

## 6. 状态文件

- 默认状态：`enabled`。
- 状态文件：已安装技能目录中的 `state.json`。
- 仓库通过 `.gitignore` 排除该文件。
- 读取失败或文件损坏时按默认开启处理，并可自动修复。

## 7. 安装与兼容

提供：

- PowerShell 安装脚本，适用于 Windows。
- Bash 安装脚本，适用于 macOS/Linux。
- 安装目标为 `${CODEX_HOME:-~/.codex}/skills/prompt-enhance`。
- 安装时复制技能主体、说明和脚本，保留已有 `state.json`。
- 不覆盖用户的其他技能，不修改 Codex 程序目录。

全局 `AGENTS.md` 的修改由安装后的说明单独指导，也可由默认安装脚本提示；安装器不得无条件覆盖现有规则文件。

## 8. 发布内容

公开仓库 `codex-smart-prompt-enhancer` 包含：

- `SKILL.md`
- `agents/openai.yaml`
- 中文 README（附英文简介）
- MIT `LICENSE`
- 安装与状态脚本
- 测试
- 隐私说明

不包含：

- 用户邮箱、姓名、主机路径或账号标识。
- 密钥、token、Cookie、认证文件。
- 本机状态文件、日志、缓存或代理配置。

## 9. 验收标准

1. 本机技能目录中存在可被 Codex 识别的 `prompt-enhance` 技能。
2. 默认开启；关闭后能持久保存；再次开启成功。
3. 非法状态输入不会破坏现有状态。
4. 安装脚本能在临时 `CODEX_HOME` 中完成干净安装，并保留已有状态。
5. 技能通过官方 `quick_validate.py` 校验。
6. 全局规则仅在备份后追加触发说明，原规则完整保留。
7. Git 仓库通过测试和敏感信息扫描后推送为公开仓库。
8. GitHub 仓库可匿名访问，README 和许可证显示正常。
